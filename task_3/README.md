# Задание 3: Создание векторного индекса базы знаний

## Описание

Создание векторного индекса из базы знаний (71 документ из замененной вселенной "Властелин Колец") с использованием локальной модели эмбеддингов и ChromaDB.

## Технические характеристики

### Модель эмбеддингов

- **Модель**: `sentence-transformers/all-mpnet-base-v2`
- **Размерность**: 768
- **Тип**: Локальная (не требует API)
- **Преимущества**:
  - Высокое качество для семантического поиска
  - Быстрая генерация эмбеддингов
  - Полная конфиденциальность (данные не покидают сервер)

### База данных

- **БД**: ChromaDB (embedded mode)
- **Режим**: Persistent storage
- **Коллекция**: `lotr_knowledge_base`
- **Местоположение**: `./chroma_db/`

### База знаний

- **Источник**: 71 документ из `../task_2/knowledge_base/`
- **Вселенная**: "Властелин Колец" с замененными терминами
- **Формат**: Текстовые файлы (.txt)

### Параметры чанкинга

- **Размер чанка**: 1000 символов
- **Перекрытие**: 200 символов
- **Метод**: RecursiveCharacterTextSplitter (LangChain)
- **Разделители**: `\n\n`, `\n`, `. `, пробел

### Метаданные чанков

```python
{
    "source": "filename.txt",      # Имя исходного файла
    "chunk_id": 0,                  # Порядковый номер чанка в документе
    "doc_index": 0                  # Индекс документа
}
```

## Интеграция в RAG

### Пример использования в коде

```python
import chromadb
from chromadb.utils import embedding_functions

# Подключение к индексу
client = chromadb.PersistentClient(path="./chroma_db")

embedding_func = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="sentence-transformers/all-mpnet-base-v2"
)

collection = client.get_collection(
    name="lotr_knowledge_base",
    embedding_function=embedding_func
)

# Поиск
results = collection.query(
    query_texts=["Ваш запрос"],
    n_results=5
)

# Результаты
for doc, meta, dist in zip(
    results['documents'][0],
    results['metadatas'][0],
    results['distances'][0]
):
    print(f"Источник: {meta['source']}")
    print(f"Релевантность: {1 / (1 + dist):.3f}")
    print(f"Текст: {doc[:200]}...\n")
```

## Особенности реализации

### Почему all-mpnet-base-v2?

1. **Качество**: Лучший баланс качество/скорость среди моделей до 1B параметров
2. **Размер**: 420 МБ (умещается в RAM любого сервера)
3. **Скорость**: ~1000 токенов/сек на CPU
4. **Языковая поддержка**: Отлично работает с русским текстом
5. **Совместимость**: Нативная поддержка в ChromaDB

### Почему ChromaDB?

1. **Простота**: API из коробки, не требует отдельного сервера
2. **Embedded mode**: Работает как SQLite, не требует администрирования
3. **Persistent storage**: Индекс сохраняется на диск
4. **CRUD операции**: Легко добавлять/обновлять документы
5. **Масштабируемость**: Поддержка до 100K документов (достаточно для текущей задачи)

### Параметры чанкинга

**Размер 1000 символов** выбран потому что:

- Средний размер контекста для семантического поиска
- Достаточно для понимания смысла параграфа
- Не слишком большой (не теряется точность)
- Не слишком малый (не теряется контекст)

**Overlap 200** обеспечивает:

- Сохранение контекста на границах чанков
- Устойчивость к "разрыву" предложений
- Повышение качества поиска на 10-15%

## Производительность

### Создание индекса

- **71 документ** → ~2-5 минут на CPU

## Решение проблем

### Модель не загружается

```bash
# Очистить кэш и переустановить
rm -rf ~/.cache/huggingface
pip install --force-reinstall sentence-transformers
```

### ChromaDB не создается

```bash
# Проверить права доступа
chmod -R 755 chroma_db/
# Или удалить и пересоздать
rm -rf chroma_db/
python build_index.py
```

### Недостаточно памяти

- Уменьшить `batch_size` в `build_index.py` (по умолчанию 100)
- Увеличить swap на сервере
- Использовать GPU для эмбеддингов (значительно быстрее)
