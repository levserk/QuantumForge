# Задание 1. Исследование моделей и инфраструктуры

## Контекст

**Компания:** QuantumForge Software (финско-эстонская, штаб-квартира в Хельсинки)

**Проблема:**

- ~18,000 Markdown файлов + ~3,000 страниц Confluence + ~250 PDF-спецификаций
- Новые инженеры тратят до 4 часов/неделю на поиск информации
- Разрозненность документации, устаревание контента

**Задача:** Выбрать технологический стек для RAG-бота корпоративной базы знаний.

| Модель                                | Скорость индексации                | Качество поиска | Стоимость          | Размер вектора |
| ------------------------------------- | ---------------------------------- | --------------- | ------------------ | -------------- |

## 3. Сравнение векторных БД

| Критерий             | FAISS                                  | ChromaDB                           |
| -------------------- | -------------------------------------- | ---------------------------------- |
| Скорость поиска      | Очень быстрая (<10ms), поддержка GPU   | Быстрая (<50ms), только CPU        |
| Скорость индексации  | Очень быстрая (10K docs/sec)           | Быстрая (5-8K docs/sec)            |
| Сложность внедрения  | Средняя (нужна обёртка для метаданных) | Простая (API из коробки)           |
| Удобство работы      | Low-level API, нет CRUD                | High-level API, есть CRUD операции |
| Стоимость владения   | $0 (open-source, in-memory)            | $0 (open-source, embedded mode)    |
| Работа с метаданными | Требует ручной реализации              | Встроенная поддержка               |
| Масштабирование      | Миллионы векторов, GPU-ускорение       | До ~100K документов (ограничения)  |

**Ограничения ChromaDB:**

- Не рассчитана на >100K документов (у QuantumForge 18K + прирост 400 страниц/мес → ~30K за год)
- Хранение embeddings в SQLite → рост файла → фрагментация при частых обновлениях
- Нет GPU-ускорения для поиска

**Преимущества FAISS:**

- Поддержка GPU (в 100 раз быстрее для больших индексов)
- Масштабируется до миллионов векторов
- Используется крупными компаниями для production

**Вывод:** Для текущих 18K документов подходит **ChromaDB** (простота внедрения). При росте до 50K+ документов рекомендуется миграция на **FAISS** с GPU-ускорением и ручной обёрткой для метаданных.

## 4. Конфигурация сервера (варианты)

### Предположения по нагрузке:

- 50 активных пользователей
- 10 запросов/день на пользователя = 500 запросов/день
- ~15,000 запросов/месяц
- Средний запрос: 1,500 токенов (вход) + 500 токенов (выход)

### Сравнение вариантов:

| Вариант                     | LLM                              | Embeddings             | Vector DB      | Сервер           | Стоимость сервера | Стоимость API | **Итого/мес** |
| --------------------------- | -------------------------------- | ---------------------- | -------------- | ---------------- | ----------------- | ------------- | ------------- |
| **1. Гибрид (рекомендуем)** | GPT-4o mini (90%) + GPT-4o (10%) | all-mpnet (локально)   | ChromaDB       | 8 vCPU, 16GB RAM | $100-150          | $5-15         | **$105-165**  |
| **2. Полное облако**        | GPT-4o mini                      | text-embedding-3-small | ChromaDB Cloud | 4 vCPU, 8GB RAM  | $50-80            | $3-5          | **$53-85**    |
| **3. Локальный GPU**        | Mistral 7B v0.3 / Llama 3 8B     | all-mpnet              | ChromaDB       | RTX 3090 24GB    | $350 (₽31,500)    | $0            | **$350**      |
| **4. Бюджетный**            | GPT-4o mini                      | all-MiniLM             | FAISS          | 4 vCPU, 8GB RAM  | $50-80            | $3-5          | **$53-85**    |

### Детализация стоимости API (Вариант 1):

**GPT-4o mini (90% запросов = 13,500/мес):**

- Входные токены: 13,500 × 1,500 = 20.25M → 20.25 × $0.15/1M = $3.04
- Выходные токены: 13,500 × 500 = 6.75M → 6.75 × $0.60/1M = $4.05
- Итого: ~$7/мес

**GPT-4o (10% запросов = 1,500/мес):**

- Входные токены: 1,500 × 1,500 = 2.25M → 2.25 × $5/1M = $11.25
- Выходные токены: 1,500 × 500 = 0.75M → 0.75 × $15/1M = $11.25
- Итого: ~$22.50/мес

**Общая стоимость API:** ~$29.50/мес (вместо $132 на старых ценах)

## Итоговые рекомендации для QuantumForge

### Выбранная конфигурация: Вариант 1 (Гибрид)

**Стек:**

- **LLM:** GPT-4o mini (основной трафик) + GPT-4o (сложные запросы)
- **Embeddings:** all-mpnet-base-v2 (локально)
- **Vector DB:** ChromaDB (embedded mode)
- **Сервер:** AWS EC2 (8 vCPU, 16GB RAM, 100GB SSD)
- **Стоимость:** ~$130-180/мес

**Обоснование выбора:**

1. **Оптимальное соотношение цена/качество:** API стоимость всего ~$30/мес при высоком качестве ответов GPT-4o mini/4o. GPT-4o mini ($0.15/$0.60) в 3+ раза дешевле устаревшего GPT-3.5-turbo.

2. **Безопасность эмбеддингов:** Документы индексируются локально (all-mpnet), векторы не покидают инфраструктуру. В OpenAI уходят только пользовательские запросы и релевантные фрагменты.

3. **Быстрое внедрение:** Компания уже использует AWS и имеет DevOps культуру. Развёртывание займёт 2-3 недели до MVP.

4. **Гибкость:** Легко переключиться между GPT-4o mini и GPT-4o в зависимости от сложности запроса. При необходимости можно мигрировать на локальную LLM (Mistral 7B v0.3 или Llama 3 8B) с минимальными изменениями кода.

5. **Масштабируемость:** ChromaDB поддерживает CRUD-операции, легко добавлять новые документы. При росте нагрузки можно увеличить ресурсы сервера или перейти на client-server режим ChromaDB.

**Путь миграции (при необходимости):**
Если возникнут строгие требования конфиденциальности (например, для 250 PDF-спецификаций), можно перейти на Вариант 3 (локальный GPU с Mistral 7B v0.3 или Llama 3 8B за $350/мес) с минимальными изменениями архитектуры.
